# Практическая работа №9: управление памятью

Симулятор распределения памяти по дисциплине «Операционные системы».
Реализованы уровни A и B. Запуск — из терминала Ubuntu через Python 3,
без сторонних библиотек.

## Возможности

- First fit — первая подходящая свободная область.
- Best fit — минимальная подходящая свободная область.
- Worst fit — максимальная подходящая свободная область.
- Разбиение свободных блоков при выделении памяти.
- Необязательное слияние соседних свободных областей (`--merge`).
- Buddy system: округление размера до степени двойки, деление блоков,
  поиск парного блока через XOR и слияние при освобождении.
- Карта памяти после каждой операции, подсчёт отказов и фрагментации.

Объём моделируемой памяти — 1024 условные единицы.

## Запуск в Ubuntu

Выполняйте команды из папки с этими файлами:

```bash
python3 --version
python3 run_ops1.py first
python3 run_ops1.py best
python3 run_ops1.py worst
python3 run_ops1.py first --merge
python3 compare.py
```

Другой входной файл:

```bash
python3 run_ops1.py best --file ops2.txt
python3 compare.py ops1.txt
```

Сохранение результатов:

```bash
python3 run_ops1.py best | tee best_result.txt
python3 compare.py | tee compare_result.txt
```

## Формат операций

```text
alloc P1 200
free P1
```

`alloc PID размер` запрашивает память, `free PID` освобождает её.
Освобождение процесса, которому ранее отказали, не меняет состояние.
`[P1:200]` обозначает занятый блок, `[-:824]` — свободный.

## Проверенные результаты на ops1

Без слияния соседних свободных блоков:

| Стратегия | Свободно | Максимальная дыра | Число дыр | Отказов | Номера операций с отказом |
|---|---:|---:|---:|---:|---|
| first | 904 | 250 | 5 | 3 | 8, 10, 12 |
| best | 624 | 250 | 5 | 2 | 10, 12 |
| worst | 904 | 250 | 5 | 3 | 8, 10, 12 |

Best fit на операции 7 выбирает блок 124 под запрос 120, оставляя 4.
Поэтому блок 300 сохраняется для запроса P6 размером 280 на операции 8.
First fit и worst fit расходуют блок 300 раньше и отклоняют этот запрос.

При слиянии у каждой fit-стратегии отказы на операциях 10 и 12.
У buddy отказы на операциях 4, 8 и 10; операция 12 проходит.

## Проверенные результаты на ops2

Все fit-стратегии в этой таблице используют слияние.
Показатели фрагментации усреднены после каждой из 200 операций.

| Подход | Отказов | Средняя внешняя фрагментация | Средняя внутренняя фрагментация, единиц |
|---|---:|---:|---:|
| first + merge | 33 | 0.4690 | 0.00 |
| best + merge | 32 | 0.3589 | 0.00 |
| worst + merge | 38 | 0.5236 | 0.00 |
| buddy | 38 | 0.3646 | 175.43 |

Внешняя фрагментация рассчитывается как `1 - largest / total`, где
`largest` — максимальный свободный блок, `total` — вся свободная память.
Если свободной памяти нет, показатель принят равным нулю.

Внутренняя фрагментация buddy — сумма разностей между размерами выданных
блоков и фактически запрошенными размерами активных процессов.
Fit-стратегии выделяют точный размер запроса и в этой модели имеют нулевую
внутреннюю фрагментацию. Служебные данные и выравнивание здесь не моделируются.

## Пример Buddy system

```bash
python3 - <<'PY'
from buddy import Buddy
b = Buddy(log=True)
b.alloc("P1", 200)
print("Занято:", b.owned)
print("Статистика:", b.stats())
b.release("P1")
print("После освобождения:", b.stats())
PY
```

Запрос 200 получает блок 256 по адресу 0. Внутренняя фрагментация — 56.
После освобождения блоки сливаются обратно в один регион 1024.

## Выводы

На данном наборе best fit со слиянием имеет меньше всего отказов: 32.
Buddy даёт близкую внешнюю фрагментацию, но тратит в среднем 175.43 единицы
на внутреннюю фрагментацию и получает 38 отказов. Результат зависит от
последовательности запросов и не означает превосходства одной стратегии
на любых нагрузках.
